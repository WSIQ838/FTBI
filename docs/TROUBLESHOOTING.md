# Troubleshooting and escalation

Development operating guide; institutional support contacts and acceptance remain outstanding. This is not a production installation guide. Record the affected workflow, time with timezone, deployed commit, role and a non-sensitive incident reference. Do not collect passwords, authentication cookies, verification codes, payment-card data or unredacted student records in support tickets.

| Symptom | Check and supported response | Escalation boundary |
| --- | --- | --- |
| Login denied | Distinguish inactive account, administrative lock, temporary failure lock and MFA requirement. Use authorized account controls with password confirmation and a reason; users may inspect/revoke their own tracked sessions. | Do not bypass MFA or make a support caller a superuser. Institutional identity verification and recovery acceptance are required. |
| Access disappeared | Check current course enrollment, publication, instructor/advisor assignment and role permissions. Revocation may intentionally remove access. | Do not grant broad administrative permissions to compensate for a missing scoped assignment. |
| Exam closed or expired | Check current closing date, explicit per-quiz extension, session expiry, submitted attempts and current approved course accommodation. A session starts on first access. | Expired unsubmitted sessions are not automatically reset. Approved extra time does not extend the closing date. Preserve assessment records for authorized academic review. |
| Registration or waitlist blocked | Check registration window, active status, manual/financial holds, capacity, prerequisite groups and the first waitlist entry. | An ineligible queue head stops promotion; do not silently skip it or alter final grades. See REGISTRAR.md. |
| Course package rejected | Check version 1/2, 2 MB upload limit, empty unpublished owned target, bounded lists, field references, module cycles and offset-aware dates. | Failed imports roll back. Export packages can contain personal information in authored text; review before sharing. External media bytes and standards packages are unsupported. |
| Upload rejected | Check format, size, shared quota and private scanner availability. Scanner failure rejects extended file uploads. | Do not disable scanning or expose private media to make uploads work. Preserve the error reference, not the rejected file in a public ticket. |
| In-app notice but no email | Check email preference/address, active account, approved SMTP, due pending records and worker history. Failed items have bounded retries; authorized staff may request a retry. | SMTP acceptance is not delivery proof; retries can duplicate email. Live SMTP and scheduler acceptance remain open. |
| Payment appears twice or does not settle | Compare payment request, provider reference, ledger and allocation/reconciliation records. Preserve provider event IDs privately. | Do not mark Stripe requests manually verified or replay real charges. Provider refunds/disputes and settlement reconciliation remain unfinished. |
| Credential issuance fails | Check issuance eligibility, configured signing requirement, certificate validity and protected key availability. | Required signing fails closed. Never disable a signing requirement just to issue an unsigned document. Trust/key-custody acceptance is separate. |
| Metrics return 401 or 404 | 401 indicates absent/wrong authorization; 404 is expected when the monitoring token is unconfigured. | Do not put tokens in URLs, logs or tickets. The endpoint is private. |
| Metrics return 503 | Inspect individual database/cache/disk/notification/backup checks. An unconfigured backup is deliberately unhealthy. | A database outage can also prevent durable failure alerts. Independent external monitoring is required. |
| Backup catalog refuses an operation | Check managed-store identity, manifest integrity, file ownership/type and active operation lock. | Do not remove an unknown lock, edit manifests to hide corruption or mark a backup restored without a verified restore. Retention defaults to a dry run. |

Production logs deliberately omit arbitrary request/exception text. An absence of stack detail is expected, not proof that no error occurred. Use restricted, approved diagnostics with synthetic reproduction and preserve evidence separately. Follow [incident response](INCIDENT_RESPONSE.md) for compromise or integrity concerns and [release status](RELEASE_STATUS.md) for unresolved dependencies.
