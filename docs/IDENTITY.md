# Institutional identity
Optional OIDC uses mozilla-django-oidc with RS256 signature verification, state and nonce handling. Configure a single trusted provider using its HTTPS endpoints and client credentials; provision each user's immutable provider subject in IdentityLink. Email address matching and automatic account creation are disabled. Existing local accounts remain available. The local MFA gate still applies to SSO sessions; institution-only users who do not have a usable local password must have their enrollment/recovery process established before enforcing local MFA. Never change providers without removing or revalidating every existing subject link.
The login view includes a basic per-IP/account cache throttle. LocMemCache is process-local and insufficient for distributed production rate limiting; use a trusted shared cache and reverse-proxy limits. The Django admin login, MFA setup, and password reset endpoints require proxy-level rate limits as well.
Provider integration is not verified until a real approved provider is configured and tested.
