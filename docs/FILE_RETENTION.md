# Reviewed file retention

Retention is disabled by default. The DataRetentionAdministration role can configure a policy, propose a bounded preview, preserve documents and independently review a preview. An enabled policy needs an institutional approval reference, an age threshold from 30 through 36,500 days and at least one retained newest version (up to 20). These are software bounds, not a legal retention recommendation. Actual institutional retention/privacy approval remains outstanding.

Policies cover obsolete private-document versions in the institutional, student or admission categories. Coursework documents, legacy coursework attachments, submission revisions, credentials and other academic/finance records are outside this erasure workflow. Current retained versions, any version with a verification/rejection record, recent files and documents with active preservation holds are excluded.

A proposal records the exact version IDs, document IDs, original sizes, digests and policy snapshot, plus its reason and author. It does not erase anything. Each preview contains at most 500 versions and 50 MB of file contents; additional eligible files require another reviewed batch. Previews expire after 24 hours. Another authorized reviewer must inspect the exact preview and explicitly confirm erasure. A changed policy, new hold, new verification, changed metadata, oversized batch or content integrity failure rejects the complete operation without erasing any payloads. Concurrent and repeated application cannot apply a batch twice.

Erasure replaces selected payload bytes in the active database with empty bytes and records the erasure time. Metadata, original names/sizes/hashes, versions, proposal, reviewer and audit references remain. Erased versions no longer consume the application storage quota, return 410 on an authorized direct download, cannot be verified afterward and are excluded from personal archives. The document history explains why a file is unavailable. This is neither full record anonymization nor guaranteed physical removal from database pages, replicas, logs, backups or external copies.

Preservation holds use a document ID and case/reference reason; they protect every version of that document. Releasing a hold requires an authorized action and a reason. The original hold and release history remain, and release alone does not erase anything. Do not enter medical evidence or unnecessary personal information in reasons. Hold management and payload erasure serialize on document/version locks; document verification rechecks erasure after acquiring its lock.

There is no automatic production retention scheduler. No institutional documents have been erased as part of development: erasure tests use disposable synthetic databases. Institutional policy approval, preservation obligations, offsite/backups retention, physical erasure assurance and a reviewed process for complete student-record deletion/anonymization remain external or unfinished work. Audit history remains in the application database and is not tamper-resistant external evidence.
